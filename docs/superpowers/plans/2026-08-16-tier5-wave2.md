# Tier 5 Wave 2 Implementation Plan — $schemaversion, Optional Function Parameters

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the two Wave 2 OData 4.01 features — the `$schemaversion` system query option (OLINGO-1326, Protocol §11.2.12) and optional function parameters via `Core.OptionalParameter` (OLINGO-1634, Protocol §11.5.4.1.1/§11.5.4.2) — server + client, tecsvc + fit proven.

**Architecture:** Spec: `docs/superpowers/specs/2026-08-12-tier5-odata401-design.md` (Features 4–5); normative quotes: `docs/superpowers/specs/2026-08-12-tier5-odata401-citations.md` (sections 4–5) — the citations file governs. `$schemaversion` threads a 14th system query option through the positional enum/matrix/parser chain, validates at handler level (`ODataApplicationException` 404), and inherits into batch parts by pre-injecting the outer option into each part's raw query string (the `/$query` rewrite precedent). Optional parameters change `EdmProviderImpl`'s strict exact-name-set overload matching into the spec's two-step rule (exact, else covering-set of exactly one) at the single choke point all four parser call sites share, with `Core.OptionalParameter` read from parameter annotations (inline AND out-of-line via the annotations map — out-of-line targets resolve only post-match today, so the matcher must consult both sources itself).

**Tech Stack:** Java 17, Maven; modules `lib/commons-api`, `lib/commons-core`, `lib/server-api`, `lib/server-core`, `lib/server-tecsvc`, `lib/server-tecsvc-servlet`, `lib/server-test`, `lib/client-api`, `lib/client-core`, `lib/odata-vocabularies`, `fit`.
