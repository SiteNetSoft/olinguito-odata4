# Tier 5 Wave 3 Implementation Plan — Key-as-Segment, Alternate Keys

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the two Wave 3 OData 4.01 features — the key-as-segment URL convention (OLINGO-1084, URL §4.3.6) as a service-level opt-in with the spec's 4-step precedence, multi-part keys and referential-constraint omission (server + client), and alternate keys (OLINGO-1570, URL §4.3.5 + `Core.AlternateKeys`) for parenthesized name=value addressing (EDM + parser + tecsvc CRUD) — tecsvc + fit proven.

**Architecture:** Spec: `docs/superpowers/specs/2026-08-12-tier5-odata401-design.md` (Features 6–7); normative quotes: `docs/superpowers/specs/2026-08-12-tier5-odata401-citations.md` (sections 6–7) — the citations file governs. Key-as-segment: the fork already carries a NON-STANDARD, model-driven partial implementation (`EdmEntitySet.isKeyAsSegmentAllowed()` / `EdmNavigationProperty.isKeyAsSegmentAllowed()`, `ResourcePathParser.canParseKeyFromSegment` + `didSetKeySegmentAsKey`, single-key only, no type validation, no precedence, no multi-part, no referential-constraint omission). Wave 3 adds a service-level flag on `ODataHandler` threaded `ODataHandlerImpl → Parser → ResourcePathParser`, replaces `didSetKeySegmentAsKey` with a spec-faithful key-segment parser (effective enablement = service flag OR model flag, so existing model-flagged behavior keeps working), fixes the client `URIBuilderImpl` key-as-segment mode (unquoted strings, `/`→`%2F`, one segment per multi-part key value), and exposes the mode in tecsvc through a second endpoint that fit hits alongside the default one. Alternate keys: `Core.AlternateKeys` (+ `AlternateKey`, `PropertyRef`) enter the vocabulary files; `EdmEntityType`/`EdmEntitySet` gain `getAlternateKeys()` (default empty; impls read type/set annotations, OLINGO-1399 raw-term fallback, top-level primitive properties only); `ParserHelper.parseKeyPredicate`'s named-predicate branch resolves a name set that is not the declared key against the alternate-key groups (exactly one complete match) and marks the resulting `UriParameter`s with the underlying property name; tecsvc `DataProvider` resolves those; canonical/edit/id/Location URLs stay primary-key (built from the entity, pinned).

**Tech Stack:** Java 17, Maven; modules `lib/commons-api`, `lib/commons-core`, `lib/server-api`, `lib/server-core`, `lib/server-tecsvc`, `lib/server-tecsvc-servlet`, `lib/server-tecsvc-quarkus`, `lib/server-test`, `lib/client-api`, `lib/client-core`, `lib/odata-vocabularies`, `lib/server-core-ext` (vocab copy), `lib/test-fixtures` (vocab copy), `fit`.

**Spec:** `docs/superpowers/specs/2026-08-12-tier5-odata401-design.md` (Features 6, 7) + `docs/superpowers/specs/2026-08-12-tier5-odata401-citations.md` (§6, §7).
