**Goal:** Close the three Wave 3 features against OASIS. **Streaming:** a primitive or complex collection can be serialized straight onto the response channel instead of being fully materialized in a `CircleStreamBuffer`, through a new `PropertyIterator` abstraction and two new `default` methods on `ODataSerializer`, with the streamed bytes pinned byte-for-byte against the buffered bytes for the same data. **Stream properties:** `Name@mediaReadLink`/`Name@mediaEditLink` are emitted whenever [OData-JSON] §4.5.12 and §3.1.1 require them — that is, whenever the link is *not* computable from the entity's own read/edit link — instead of only at `metadata=full`, where today a service whose stream lives on a different host silently returns a payload from which the stream is unreachable; custom-term instance annotations on stream properties are verified and pinned; and the XML serializer, which today feeds a `Link` object into `EdmStream.valueToString` with undefined results, is made to refuse a stream-property value explicitly. **Async:** the decision to process a request asynchronously moves out of user processor code into the framework — a `server-api` SPI registered through the existing `register(OlingoExtension)` slot, consulted by `ODataHandlerImpl` before dispatch, which owns the 202 + `Location` + `Preference-Applied` response, the status-monitor resource and both §11.6 result shapes (the `application/http` envelope and the unwrapped `AsyncResult` form the current implementation never emits) — with tecsvc's four duplicated `hasRespondAsync()` checks deleted and the fit async suites as the behavioral pin.

**Architecture:** Four seams.

(1) **Streamed collections.** `ODataSerializer` (`lib/server-api/.../serializer/ODataSerializer.java`) declares `entityCollectionStreamed` but nothing for primitive or complex collections; the interface has **no `default` methods today**, and `AbstractODataSerializer`/`ODataJsonSerializer`/`ODataXmlSerializer` are its only implementors in this repo. The streamed entity path is a two-part shape: `entityCollectionStreamed` (`ODataJsonSerializer.java:301`) *only* builds a lazy `ODataWritableContent` and the actual writing lives in the public `entityCollectionIntoStream` (`:308`), which creates a `JsonGenerator` directly on the caller's `OutputStream` (no `CircleStreamBuffer`) and reuses the same `writeEntitySet` helper the buffered path uses. Wave 3 mirrors that shape exactly: a `PropertyIterator` in `commons-api` (an `Iterator<Property>` carrying the collection's `count`/`next`, modelled on `EntityIterator`), two new `default` methods on `ODataSerializer` that throw the existing `NOT_IMPLEMENTED_SERIALIZER` error so every downstream implementor keeps compiling, `primitiveCollectionIntoStream`/`complexCollectionIntoStream` on `ODataJsonSerializer` reusing the existing private array-body writers `writePrimitiveCollection` (`:1145`) and `writeComplexCollection` (`:1183`), and a new `StreamContentForJsonProperty` shape plus a builder overload on `ODataWritableContent`. tecsvc streams two already-pinned endpoints (`ESCollAllPrim(<key>)/CollPropertyString` and `ESMixPrimCollComp(<key>)/CollPropertyComp`) so the equivalence is proved against tests that already assert those exact bytes.

(2) **Stream-property control information.** The single write site is the `EdmPrimitiveTypeKind.Stream` branch of `ODataJsonSerializer.writePrimitiveValue` (`:1304-1322`): `mediaEtag`/`mediaContentType` are written whenever metadata is not `none`, but `mediaReadLink`/`mediaEditLink` are gated on `isODataMetadataFull` alone. [OData-JSON] §4.5.12 makes at least one of the two links a **MUST** in responses "if they don't follow standard URL conventions … **or** if metadata=full is requested", and §3.1.1 makes control information mandatory at `minimal` "for cases where actual values are not the same as the computed values". The gate becomes: at `full`, unchanged; at `minimal`, write the link when its href is not the computed one; at `none`, nothing. "Computed" is defined once, in one helper, as the entity's own read/edit link followed by `/` and the stream property's name. The value plumbing is untouched — a stream property is a `Property` with `ValueType.PRIMITIVE` whose value is a `Link`, detected by `isStreamProperty` (`:922`), and the `name@…` prefix is the property's own name.

(3) **Stream properties in XML.** `ODataXmlSerializer` has no stream-property code at all (zero `media*` hits): `writePrimitive` (`:1022`) hands the `Link` object to `EdmStream.valueToString`, which is not defined for it. This wave makes that path throw `SerializerException.MessageKeys.UNSUPPORTED_PROPERTY_TYPE` explicitly, exactly as Wave 2 did for geospatial and entity-typed values, rather than inventing Atom markup for which this milestone holds no citation.

(4) **Framework-level async.** `ODataHandlerImpl.processInternal` (`:154-207`) validates the version, parses the URI, validates it, checks `$schemaversion` and then dispatches exactly once (`:200`); `process` (`:108-152`) wraps that in the full catch chain that turns any failure into an error response. The `Prefer` header is never read anywhere in server-core — every async decision lives in tecsvc (`TechnicalBatchProcessor.java:54`, `TechnicalEntityProcessor.java:204`, `:465`, `:593`, four byte-identical copies) and the status monitor is a servlet in `server-tecsvc-servlet`. Wave 3 adds `AsyncSupport extends OlingoExtension` in `server-api`, registered through the existing `register(OlingoExtension)` `instanceof` chain (`ODataHandlerImpl.java:445-455`) — no interface change, no new registration overload. The handler consults it in two places: before anything else, to recognize a status-monitor request; and after URI validation but before dispatch, to submit the invocation when `respond-async` was requested. The invocation the handler submits is a closure over the **same** already-parsed `UriInfo` and a **detached copy** of the request whose body has been read into memory, run through the same catch chain as a synchronous request, so an asynchronous failure produces the same error payload a synchronous one would.

class PropertyStreamedDefaultsTest {

  /** A PropertyIterator over a fixed list, used by this test and reused by Task 2's tests. */
  static PropertyIterator iteratorOver(final String name, final ValueType valueType, final List<?> values) {
    final Iterator<?> delegate = values.iterator();
    final PropertyIterator iterator = new PropertyIterator() {
      @Override
      public boolean hasNext() {
        return delegate.hasNext();
      }

      @Override
      public Property next() {
        final Object value = delegate.next();
        return new Property(null, name, elementValueType(valueType), value);

```java
package org.sitenetsoft.olinguito.commons.api.data;

import java.net.URI;
import java.util.Iterator;

import org.sitenetsoft.olinguito.commons.api.ex.ODataNotSupportedException;

/**
 * Iterator over the elements of a single collection-valued property, for use with the streamed
 * serializer entry points {@code ODataSerializer.primitiveCollectionStreamed} and
 * {@code complexCollectionStreamed}.
 *
 * <p>This is the property-level counterpart of {@link EntityIterator}: it carries the metadata the
 * collection as a whole needs ({@link #getName()}, {@link #getValueType()}, {@link #getCount()},
 * {@link #getNext()}), and yields one {@link Property} per element, each holding a single element
 * value. {@link #getValueType()} reports the value type of the collection
 * ({@code COLLECTION_PRIMITIVE}, {@code COLLECTION_ENUM}, {@code COLLECTION_GEOSPATIAL} or
 * {@code COLLECTION_COMPLEX}), exactly as a buffered collection-valued {@link Property} does.</p>
 */
public abstract class PropertyIterator implements Iterator<Property> {

  private String name;

  private ValueType valueType;

  private URI next;

  private Integer count;

  @Override
  public abstract boolean hasNext();

  /**
   * {@inheritDoc}
   * <p/>
   * Which is one element of the collection, wrapped in a {@link Property}, for this type of
   * iterator.
   */
  @Override
  public abstract Property next();

  /**
   * {@inheritDoc}
   * <p/>
   * <b>ATTENTION:</b> <code>remove</code> is not supported by default.
   */
  @Override
  public void remove() {
    throw new ODataNotSupportedException("Property Iterator does not support remove()");
  }

  /** Gets the name of the collection-valued property. */
  public String getName() {
    return name;
  }

  /** Sets the name of the collection-valued property. */
  public void setName(final String name) {
    this.name = name;
  }

  /** Gets the value type of the collection as a whole. */
  public ValueType getValueType() {
    return valueType;
  }

  /** Sets the value type of the collection as a whole. */
  public void setValueType(final ValueType valueType) {
    this.valueType = valueType;
  }

  /**
   * Gets the inline count.
   *
   * <p>Note: the inline count is limited to {@code Integer.MAX_VALUE}. The OData specification
   * defines {@code @odata.count} as {@code Edm.Int64}; widening this to {@code long} is deferred
   * (OLINGO-1540) because it would be a breaking public-API change.</p>
   */
  public Integer getCount() {
    return count;
  }

  /** Sets the inline count. */
  public void setCount(final Integer count) {
    this.count = count;
  }

  /** Gets the next link. */
  public URI getNext() {
    return next;
  }

  /** Sets the next link. */
  public void setNext(final URI next) {
    this.next = next;
  }
}
```

   * Writes a primitive collection straight onto {@code outputStream}, producing byte-for-byte the

   *
   * <p>The member order — context, metadata ETag, type, count, value, next link — is the order
   * [OData-JSON] section 4.4 requires of a streaming payload: the context control information first
   * and the count before the value.</p>
   */
  public void primitiveCollectionIntoStream(final ServiceMetadata metadata, final EdmPrimitiveType type,
      final PropertyIterator properties, final PrimitiveSerializerOptions options,
      final OutputStream outputStream) throws SerializerException {
    // PrimitiveSerializerOptions has no omit-values option; reset the shared omitNulls field so it
    // cannot leak in from a prior entity()/entityCollection() call on this same instance.
    omitNulls = false;
    try (JsonGenerator json = new JsonFactory().createGenerator(outputStream)) {
      json.writeStartObject();
      writeContextURL(checkContextURL(options == null ? null : options.getContextURL()), json);
      writeMetadataETag(metadata, json);
      if (isODataMetadataFull) {
        json.writeStringField(constants.getType(), "#Collection(" + type.getFullQualifiedName().getName() + ")");
      }
      if (options != null && options.getCount() != null && options.getCount().getValue()) {
        writeInlineCount("", properties.getCount(), json);
      }
      json.writeFieldName(Constants.VALUE);
      json.writeStartArray();
      while (properties.hasNext()) {
        final Property element = properties.next();
        writePrimitiveCollectionElement(type, properties.getName(), properties.getValueType(),
            element == null ? null : element.getValue(),
            options == null ? null : options.isNullable(),
            options == null ? null : options.getMaxLength(),
            options == null ? null : options.getPrecision(),
            options == null ? null : options.getScale(),
            options == null ? null : options.isUnicode(), json);
      }
      json.writeEndArray();
      if (properties.getNext() != null) {
        json.writeStringField(constants.getNextLink(), properties.getNext().toASCIIString());
      }
      json.writeEndObject();
    } catch (final IOException e) {
      throw new SerializerException(IO_EXCEPTION_TEXT, e, SerializerException.MessageKeys.IO_EXCEPTION);
    }

**Files:**

- Produces: `ODataJsonSerializer` writes `Name@mediaReadLink`/`Name@mediaEditLink` at `metadata=minimal` for non-computable links. Task 6 relies on this being done and does not re-edit the JSON serializer.

**The rule, quoted:**

[OData-JSON] §4.5.12: *"For media entities and stream properties at least one of the control information mediaEditLink and mediaReadLink MUST be included in responses if they don't follow standard URL conventions as defined in [OData-URL] or if metadata=full is requested."* — and *"The media\* control information is not written in responses if metadata=none is requested."*

[OData-JSON] §3.1.1: *"In addition, control information MUST appear in the payload for cases where actual values are not the same as the computed values and MAY appear otherwise."*

So there are three cases, and today's code implements only the middle column of the first row:

| metadata level | `mediaEtag` / `mediaContentType` | `mediaReadLink` / `mediaEditLink` |
|---|---|---|
| `none` | never (unchanged) | never (unchanged) |
| `minimal` | when set (unchanged) | **when the href is not the computed one** (new; today never) |
| `full` | when set (unchanged) | always (unchanged) |

**"Computed" is defined once**, and this definition is a decision, not a quotation — §4.5.12 says "standard URL conventions relative to the read link of the entity" without writing the URL out. The decision: the computed link of stream property `P` on an entity whose edit link (or, absent that, id) is `E` is `E + "/" + P`. When the entity's link cannot be determined — which is the case for a stream property nested inside a complex value, where the serializer holds a `ComplexValue` and not an `Entity` — nothing is computable and the link is therefore always written. Writing more than the minimum is explicitly permitted by §3.1.1's "and MAY appear otherwise".

      final Linked linked, final JsonGenerator json) throws IOException {

      return;
    }

      json.writeStringField(name + constants.getMediaEtag(), stream.getMediaETag());

    if (href == null || !(linked instanceof Entity entity)) {

        ? entity.getEditLink().getHref()

package org.sitenetsoft.olinguito.server.api.async;

/**
 * Service provider interface a service implements to let the framework process requests
 * asynchronously, as described in [OData-Protocol] section 11.6 (Asynchronous Requests) and section
 * 8.2.8.8 (Preference respond-async).
 *
 * <p>Register an implementation with {@code ODataHandler.register(OlingoExtension)}. With none
 * registered, the {@code respond-async} preference is ignored and not echoed, which is what a
 * service that does not support asynchronous processing must do: section 8.2.8.8 makes processing
 * asynchronously a MAY, and section 11.6 forbids answering 202 without the preference — never the
 * other way round.</p>
 *
 * <p>The implementation owns three things: where results are kept, on what thread they are
 * produced, and what the status monitor's URL looks like. Everything else — the 202 response, the
 * {@code Location} and {@code Preference-Applied} headers, the monitor's status codes and both
 * result representations — belongs to the framework and is not this interface's business.</p>
 */
public interface AsyncSupport extends OlingoExtension {

  /**
   * Whether this request addresses a status monitor resource this service minted.
   *
   * <p>Called before the request is parsed as an OData URI, because a monitor URL need not be one:
   * section 11.6 requires only that "the status monitor resource URL MUST differ from any other
   * resource URL".</p>
   */
  boolean isStatusMonitorRequest(ODataRequest request);

  /**
   * Accepts an invocation for asynchronous execution and returns the absolute URL of the status
   * monitor resource that will report on it — the value the framework puts in the {@code Location}
   * header of its 202 Accepted response (section 11.6, and section 8.3.3).
   *
   * <p>The invocation must not be run on the calling thread: the caller is about to return 202.</p>
   */
  String submit(ODataRequest request, AsyncInvocation invocation);

  /** The current state of the monitor resource this request addresses. */
  AsyncResult resolve(ODataRequest request);

  /**
   * Cancels the invocation this monitor request addresses, returning whether cancellation happened.
   *
   * <p>Section 11.6: a DELETE to the status monitor requests cancellation, and "if a delete request
   * is not supported by the service, the service returns 405 Method Not Allowed" — which is what
   * the framework answers when this returns {@code false}, its default. A service that returns
   * {@code true} guarantees section 11.6's "no observable change has occurred as a result of a
   * canceled request".</p>
   */
  default boolean cancel(final ODataRequest request) {
    return false;
  }

  /**
   * The value, in seconds, for the optional {@code Retry-After} header of a 202 response, or
   * {@code null} to omit it.
   *
   * <p>Section 8.3.7 makes the header a MAY and specifies only "the duration of time, in seconds";
   * there is no specified format beyond that, so the value is the service's to choose.</p>
   */
  default Integer getRetryAfter() {
    return null;
  }
}
```

`AsyncInvocation` is a `@FunctionalInterface` with a single `ODataResponse invoke()`; document that it never throws — the framework hands over a closure that has already turned any failure into an error response, so an implementation stores whatever it returns.

`AsyncResult` is a small immutable value class: a private constructor, three static factories, `getState()`, `getResponse()`, and `equals`/`hashCode`/`toString` are not required. `completed(null)` throws `IllegalArgumentException` — a completed result without a response is a programming error the monitor path cannot render.

      final ODataResponse response) throws ODataLibraryException {

    final String location = asyncSupport.submit(detached, () -> {

   * original — the body is read into memory, because an {@code InputStream} handed over by a
   * servlet container is not valid once the response has been sent.
   */
  private static ODataRequest detach(final ODataRequest request) throws ODataLibraryException {
    final ODataRequest copy = new ODataRequest();
    copy.setMethod(request.getMethod());
    copy.setProtocol(request.getProtocol());
    copy.setRawBaseUri(request.getRawBaseUri());
    copy.setRawODataPath(request.getRawODataPath());
    copy.setRawQueryPath(request.getRawQueryPath());
    copy.setRawRequestUri(request.getRawRequestUri());
    copy.setRawServiceResolutionUri(request.getRawServiceResolutionUri());
    for (final Map.Entry<String, List<String>> header : request.getAllHeaders().entrySet()) {
      copy.addHeader(header.getKey(), header.getValue());
    }
    if (request.getBody() != null) {
      try {
        copy.setBody(new ByteArrayInputStream(request.getBody().readAllBytes()));
      } catch (final IOException e) {
        throw new DeserializerException("Could not buffer the request body for asynchronous processing.",

  /**
   * Serves a status monitor resource ([OData-Protocol] section 11.6).
   */
  private void handleStatusMonitor(final ODataRequest request, final ODataResponse response)
      throws ODataLibraryException {
    if (request.getMethod() == HttpMethod.DELETE) {
      if (asyncSupport.cancel(request)) {
        response.setStatusCode(HttpStatusCode.NO_CONTENT.getStatusCode());
      } else {
        response.setStatusCode(HttpStatusCode.METHOD_NOT_ALLOWED.getStatusCode());
        response.setHeader(HttpHeader.ALLOW, HttpMethod.GET.name());
      }
      return;
    }
    final AsyncResult result = asyncSupport.resolve(request);
    switch (result.getState()) {
    case NOT_FOUND:
      response.setStatusCode(HttpStatusCode.NOT_FOUND.getStatusCode());
      break;
    case RUNNING:
      response.setStatusCode(HttpStatusCode.ACCEPTED.getStatusCode());
      response.setHeader(HttpHeader.LOCATION, request.getRawRequestUri());
      final Integer retryAfter = asyncSupport.getRetryAfter();
      if (retryAfter != null) {
        response.setHeader(HttpHeader.RETRY_AFTER, retryAfter.toString());
      }
      break;
    case COMPLETED:
      writeAsynchronousResult(request, response, result.getResponse());
      break;
    default:
      throw new ODataRuntimeException("Unknown asynchronous result state " + result.getState());
    }
  }

  /**
   * Writes the completed result in whichever of section 11.6's two shapes the request asks for: the
   * RFC 7230 HTTP message wrapped in {@code application/http}, or the result itself with an
   * {@code AsyncResult} header carrying its status code.
   */
  private void writeAsynchronousResult(final ODataRequest request, final ODataResponse response,
      final ODataResponse result) throws ODataLibraryException {
    if (wantsHttpMessage(request)) {
      response.setStatusCode(HttpStatusCode.OK.getStatusCode());
      response.setHeader(HttpHeader.CONTENT_TYPE, ContentType.APPLICATION_HTTP.toContentTypeString());
      response.setContent(odata.createFixedFormatSerializer().asyncResponse(result));
    } else {
      response.setStatusCode(HttpStatusCode.OK.getStatusCode());
      for (final Map.Entry<String, List<String>> header : result.getAllHeaders().entrySet()) {
        response.addHeader(header.getKey(), header.getValue());
      }
      response.setHeader(HttpHeader.ASYNC_RESULT, Integer.toString(result.getStatusCode()));
      if (result.getContent() != null) {
        response.setContent(result.getContent());
      } else if (result.getODataContent() != null) {
        response.setODataContent(result.getODataContent());
      }
    }
  }

  /**
   * Section 11.6: the wrapped form is required when the monitor request "includes an OData-MaxVersion
   * header with a value of 4.0 and no Accept header, or an Accept header that includes
   * application/http".
   */
  private static boolean wantsHttpMessage(final ODataRequest request) {
    final String accept = request.getHeader(HttpHeader.ACCEPT);
    if (accept != null && accept.contains(ContentType.APPLICATION_HTTP.toContentTypeString())) {
      return true;
    }
    final String maxVersion = request.getHeader(HttpHeader.ODATA_MAX_VERSION);
    return accept == null && maxVersion != null && ODataServiceVersion.V40.toString().equals(maxVersion.trim());
  }
```

  @Override

    final AsyncRunner runner = LOCATION_2_ASYNC_RUNNER.get(request.getRawRequestUri());

    }

- [ ] **Step 2: Record every deviation**

Append to the design spec's numbered "Recorded deviations" list, continuing from 18. At minimum, from the tasks above:

- The streamed collection writers emit no operations and no instance annotations, because a `PropertyIterator` carries neither; the buffered writers do.
- Streamed collections are JSON-only; `ODataXmlSerializer` inherits the not-implemented defaults deliberately.
- The stream-property data model carries one `Link` per property, so a service can publish a read link or an edit link, never both, and §4.5.12's "mediaReadLink MUST be included if its value differs from the value of the associated mediaEditLink" is unreachable.
- The computed stream link is defined as `<entity edit link or id>/<property name>`; §4.5.12 says "standard URL conventions" without writing the URL out.
- A stream property inside a complex value has no computable link and therefore always publishes one.
- Stream properties are refused in XML: [OData-Atom] is outside this milestone's cited sources.
- `Retry-After` is whatever the registered `AsyncSupport` returns, and absent by default; §8.3.7 specifies only "the duration of time, in seconds".
- The async wrapper omits `Content-Transfer-Encoding` (§11.7.7.1's mention is about multipart batch parts).
- A monitor request with neither `Accept` nor `OData-MaxVersion` gets the unwrapped `AsyncResult` form — §11.6's two sentences do not partition the space, and §13.2.1 makes `AsyncResult` the 4.01 Minimal MUST.
- tecsvc's monitor is one-shot: a second GET after retrieval answers 404, where §11.6 makes 404 correct after a DELETE or a long wait. Existing pinned behavior of the test service, not of the library.
- `callback` is parsed and echoed but never invoked (§8.2.8.2 is a MAY).
- Cancellation is not implemented by tecsvc, so DELETE on its monitor answers 405 — which §11.6 names as the correct answer for a service that does not support it.
