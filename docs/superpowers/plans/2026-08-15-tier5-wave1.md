# Tier 5 Wave 1 Implementation Plan — matchesPattern, omit-values, /$query

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the three Wave 1 OData 4.01 features — the `matchesPattern` filter function (OLINGO-1539), the `Prefer: omit-values=nulls` preference (OLINGO-1598), and `/$query` POST-body query options (OLINGO-1643) — server + client, tecsvc + fit proven.

**Architecture:** Spec: `docs/superpowers/specs/2026-08-12-tier5-odata401-design.md` (Features 1–3); normative quotes: `docs/superpowers/specs/2026-08-12-tier5-odata401-citations.md` (sections 1–3). All three features are additive; with no new syntax/header in play, behavior is byte-identical (pinned). matchesPattern threads a new `MethodKind` through the four existing MethodKind switches; omit-values adds a serializer option consumed at the single null-writing choke point `ODataJsonSerializer.writeProperty`; `/$query` is a raw-request rewrite in `ODataHandlerImpl.processInternal` before the URI parser runs.

**Tech Stack:** Java 17, Maven; modules `lib/commons-api`, `lib/server-api`, `lib/server-core`, `lib/server-tecsvc`, `lib/server-test`, `lib/client-api`, `lib/client-core`, `fit`.

public VisitorOperand matchesPattern() throws ODataApplicationException {
  List<String> stringParameters = getParametersAsString();
  if (stringParameters.contains(null)) {
    return new TypedOperand(null, EdmNull.getInstance());
  }
  try {
    return new TypedOperand(
        java.util.regex.Pattern.compile(stringParameters.get(1)).matcher(stringParameters.get(0)).find(),

  }
}
