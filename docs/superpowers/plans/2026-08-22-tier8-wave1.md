# Tier 8 Wave 1 — Derived-Type Casts and Single-Valued Navigation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make derived-type casts and bare single-valued navigation properties evaluate correctly in expressions, closing [OData-Protocol] §13.1.2 item 4 and §13.2.2 item 3.

**Architecture:** All four defects live in the evaluator, not the parser — every construct here already parses. The work replaces a collection-narrowing special case in `TechnicalProcessor` with the general per-instance rule in `ExpressionVisitorImpl`, lifts a 501 on bound-function casts, and repairs an NPE on bare navigation properties.

**Tech Stack:** Java 17, Maven, JUnit 5 in `lib/**`, JUnit 4 via the vintage engine in `fit/`.

**Spec:** `docs/superpowers/specs/2026-08-22-tier8-design.md` (citations: `docs/superpowers/specs/2026-08-22-tier8-citations.md`)

    assertEquals(0, entityCount("ESTwoPrim?$filter=olingo.odata.test1.ETBase/AdditionalPropertyString_5"

  private int entityCount(final String pathAndQuery) throws IOException {
    final String content = body(pathAndQuery);
    final int start = content.indexOf("\"value\":[");
    assertTrue("expected a collection response: " + content, start >= 0);
    // Every tecsvc entity in these sets carries PropertyInt16, so counting it counts entities.
    return content.substring(start).split("\"PropertyInt16\"", -1).length - 1;
  }

  private String body(final String pathAndQuery) throws IOException {
    final HttpURLConnection connection = connect(pathAndQuery);
    assertEquals(pathAndQuery, HttpStatusCode.OK.getStatusCode(), connection.getResponseCode());
    return read(connection);
  }

  private void assertStatus(final HttpStatusCode expected, final String pathAndQuery) throws IOException {
    assertEquals(pathAndQuery, expected.getStatusCode(), connect(pathAndQuery).getResponseCode());

  private HttpURLConnection connect(final String pathAndQuery) throws IOException {
    final URL url = new URL(SERVICE_URI + pathAndQuery.replace(" ", "%20").replace("'", "%27"));
    final HttpURLConnection connection = (HttpURLConnection) url.openConnection();
    connection.setRequestMethod(HttpMethod.GET.toString());
    connection.setRequestProperty(HttpHeader.ACCEPT, APPLICATION_JSON);
    connection.connect();
    return connection;
  }

  private static String read(final HttpURLConnection connection) throws IOException {
    final InputStream stream = connection.getResponseCode() >= 400
        ? connection.getErrorStream() : connection.getInputStream();
    return stream == null ? "" : new String(stream.readAllBytes(), StandardCharsets.UTF_8);
  }

  @Override
  protected ODataClient getClient() {
    return null;
  }
}

## Self-review

**Spec coverage.** §13.1.2 item 4 → Tasks 1, 2, 3 (casts in expressions) and 5 (casts on operation results). §13.2.2 item 3 → Task 4. Items 5, 8 and 9 are Wave 2 by design. The spec's D1 equivalence requirement is enforced by Tasks 2 and 3 both re-running `DerivedAndMixedTypeTestITCase` unedited.

**Type consistency.** `isInstanceOf(Entity, EdmType)` is defined in Task 2 on `ExpressionVisitorImpl`; `isCompatible(Entity, EdmType)` is defined in Task 5 on `TechnicalProcessor`. They are deliberately separate methods on classes with no shared base, and the plan says so rather than implying a shared helper. `entityCount(String)`, `body(String)`, `assertStatus(HttpStatusCode, String)` and `connect(String)` are all defined in Task 1 and used by Tasks 3, 4 and 5.

**Known soft spots, stated rather than hidden.** Task 3's test may pass immediately after Task 2 — the plan says to keep it and remove the special case anyway, because the removal is what makes the behavior general. Task 4's `TypedOperand` may not accept an entity-typed value; a fallback is given. Task 5's function import name must be confirmed against the model before the test is written, and its `blockTypeFilters` removal may leave an empty method, which the plan says to delete rather than leave.
